## 2. QUIC websocket/tcp dispatch

- Dispatch is faithful to cloudflared's `dispatchRequest` (`quic_connection.go:220-240`): HTTP/Websocket → HTTP proxy path with `isWebsocket` flag, TCP → ProxyTCP with `Dest`. libcfd: `serve_stream` switches on `ConnectionType` (`src/serve.rs:51-57`) → `handle_quic_http` / `handle_quic_websocket` / `handle_quic_tcp`. `request_client_stream.go`/`request_server_stream.go` framing: `[6-byte data signature][2-byte "01"]` + capnp ConnectRequest, response mirror — byte-exact (`serve.rs:111-119`, verified in Phase A against `tunnelrpc/quic/protocol.go`). The mock edge writes the request preamble with the same codec and reads the response preamble (`loopback_test.rs:270-295`), and `quic_websocket_tcp_round_trip` asserts HttpStatus=101 + `HttpHeader:Sec-WebSocket-Accept` for websocket and an error-free empty-metadata ack for TCP — matching `streamReadWriteAcker.AckConnection` (empty metadata, `quic_connection.go:262-272`) and the 101-across-QUEUE metadata the httpResponseAdapter sends (`quic_connection.go:298-306`).
- Raw byte pumping + stream EOF: `pump` (`src/serve.rs:169-189`) copies both directions with backpressure (quiche flow control / h2 capacity reservation) until either side EOFs, then closes both write halves. WebSocket 101 + accept headers come from the consumer's `WebSocketConnection.response` and are sent as ConnectResponse metadata with HttpStatus. QUIC stream EOF uses quiche FIN (native), consistent with advertising `support_quic_eof` (`control.rs:18-22`).
- Deliberate deviation: edge-initiated RPC streams (session/configuration manager) are answered with `unimplemented` exceptions (`serve.rs:96-108`); cloudflared serves real interfaces (`cloudflared_server.go`). Acceptable and documented — HA sessions and remote config are out of Phase B scope — but it is a hard limitation to note before real-edge validation of those features.
- `cf-trace-id`/FlowID from request metadata are dropped (`serve.rs:206-231`), Phase A carryover; tracing-only loss, and the edge treats these as informational.

## 3. Origins

- `HttpOrigin`/`WebSocketOrigin`/`TcpOrigin` trait shapes (`src/origin/mod.rs`): all `Send + Sync`, RPITIT futures `+ Send`, object-safe `*Dyn` variants; blanket `impl HttpOrigin for F` for closures; consumers own all origin I/O (websocket handshake and TCP dial happen inside the consumer's `connect`, `origin/mod.rs:70-95`; libcfd never dials a local origin service). **Matches AGENTS.md "consumers own origin I/O".**
- `Duplex` (`origin/mod.rs:24-58`): `ReadHalf`/`WriteHalf` are `Pin<Box<dyn futures_io::AsyncRead/AsyncWrite + Send>>` — runtime-agnostic (no tokio types), `Send`, split/rejoin available. The examples adapt tokio sockets with `tokio_util::compat` on the consumer side, which is the consumer's choice.
- `Origin` dispatch struct (`origin/mod.rs:107-140`): required `http`, optional `websocket`/`tcp`; both transports dispatch through it. Missing handlers get a 502 stream error (`serve.rs:69,85`; `h2/mod.rs:206,218`), matching cloudflared's WriteErrorResponse(502) behavior.
- `pump` (`serve.rs:169-189`): backpressure via `futures_util::io::copy` + poll-write capacity gating; half-close: closes both write halves when one direction ends (matches cloudflared's bidirectional-close on websocket/tcp streams); errors propagate to the caller (h2: `tracing::debug!`; quic: task error logged). One asymmetry: h2 drops the stream read side without an explicit RST when pump ends while the edge is still sending — the h2 crate handles this correctly by RST_STREAM + `release_closed_capacity` when the last stream ref drops (verified in h2 0.4.15 `streams.rs` `drop_stream_ref`/`maybe_cancel`), so no flow-control leak on the H2 path.
- QUIC: after a response, unread request bodies are drained up to 256 KB / 5 s (`drain_unread`, `serve.rs:250-276`); beyond that the stream is abandoned without a read-side reset (`stream_shutdown(Read)`), so large abandoned uploads consume the 30 MiB connection window without release (cloudflared cancels the whole stream via `defer stream.Close()` at `quic_connection.go:169`). Residual risk from Phase A; needs the specific pattern (origin ignores request body + upload > 256 KB).

## 4. Tunnel abstraction

- `Tunnel` internally-tagged enum (`src/tunnel.rs:16-23`, `#[serde(tag = "type", rename_all = "snake_case")]`) with accessors `account_tag/tunnel_secret/tunnel_id/tunnel_id_bytes/hostname`; `QuickTunnel` and `NamedTunnel` all derive `Serialize`/`Deserialize`. Matches the AGENTS.md Phase B requirement.
- `NamedTunnel` serde shape vs cloudflared credentials file: cloudflared's `connection.Credentials{AccountTag string; TunnelSecret []byte; TunnelID uuid.UUID; Endpoint string}` has no json tags, so the file keys are exactly `AccountTag`, `TunnelSecret` (Go `[]byte` → standard base64), `TunnelID` (UUID string), `Endpoint` (`cmd/cloudflared/tunnel/subcommands.go:308`, `subcommand_context.go:114,251`; `connection/connection.go:63-68`). libcfd: `#[serde(rename = "AccountTag")]`, `#[serde(rename = "TunnelSecret", with = "secret_codec")]` (STANDARD base64), `#[serde(rename = "TunnelID")]`, `#[serde(rename = "Endpoint", default, skip_serializing_if = "Option::is_none")]` (`tunnel.rs:126-139`). **Exact key names/casing/base64 match**; round-trip test asserts the literal JSON. `Endpoint` omitted when `None` (Go always emits `""` for empty) is a cosmetic difference, both parse the other's output. `from_credentials_file` (`tunnel.rs:141-151`) validates non-empty TunnelID.
- Registration refactor: `register_on_stream<S: AsyncStream>` (`control.rs:44-97`) is generic over the stream and shared by QUIC (stream 0) and H2 (control-stream body). Both pass `ConnectionOptions` with the Phase-A-mandated fields now populated: `defaultFeatures` list exactly matches cloudflared `features/features.go:19-25` (`control.rs:15-22`), `origin_local_ip` from the actual socket (`connector.rs:126,163`), `num_previous_attempts` from the attempt counter. EDUPCONN → `DuplicateConnection` error + release; `updateLocalConfiguration` when not remotely managed (connIndex is always 0 in libcfd, so cloudflared's `connIndex == 0` condition is equivalent); `unregister` bounded by grace period. The shared code is correct for both transports: the only transport-specific parts are the stream itself and the timeout wrapper.
- Minor: `client_id` is randomized per registration (`control.rs:52-55`) vs cloudflared's persistent connector UUID; registration timeout is `connect_timeout` (15 s) vs cloudflared's RPC timeout (5 s, `cmd.go` `RpcTimeout`).

## 5. EdgeConnector

- Transport selection `Transport::{Auto,Quic,H2}` (`connector.rs:14-24`), `select_transport` (`connector.rs:145-157`): Auto starts QUIC, switches to H2 after `max_quic_failures` (default 3) consecutive failures. cloudflared: `selectNextProtocol` falls back when the backoff hits max retries (default `--retries` = 5) **or immediately on `isQuicBroken`** (idle timeout / "operation not permitted", `tunnel.go:312-377`). libcfd's trigger differs (count of any failure, threshold 3) — approximation, not exact.
- Edge address rotation: iterates all discovered edges per round (`connector.rs:88-110`), re-discovering each round, `continue` on EDUPCONN. cloudflared's `IpAddrFallback` keeps the current address and rotates only on dup-conn/idle-timeout/dial errors (`tunnel.go:138-175`). Behaviorally adequate, structurally different.
- QUIC→H2 fallback: permanent once thresholds are reached (quic_failures keeps rising). cloudflared stays on the fallback protocol too. **Equivalent.**
- Backoff schedule: `retry_delay` = uniform in `[0, base * 2^retries)`, exponent capped at 30, nanosecond cap 2^62 (`connector.rs:160-169`) — the formula matches cloudflared's `BackoffTimer` (`retry/backoffhandler.go:70-84`), and the unit tests bound-check it. **But the defaults differ:** libcfd base 10 s vs cloudflared's protocol-level base 1 s (`supervisor.go:215` uses `retry.DefaultBaseTime` = 1 s), and libcfd has no grace-period reset (`SetGracePeriod`, `backoffhandler.go:104-110`) — `attempt` never resets, though in practice libcfd only reconnects after consecutive failures, so the monotonic counter is close to cloudflared's retries counter for the common case.
- Permanent errors: `Error::is_permanent` → `RegistrationFailure::Permanent` → `return Err` (`error.rs:70-76`, `connector.rs:103`) — mirrors cloudflared's `!err.Permanent` split. EDUPCONN → next edge, not permanent.
- `run_quick_tunnel` (`run.rs:52-69`) is preserved on top of `EdgeConnector` with `Transport::Quic` (cloudflared forces QUIC for quick tunnels); `RunOptions` → `EdgeOptions` conversion. Correct.
- Deviations worth noting: (a) `discover_edges` failure aborts the run (`connector.rs:91`) instead of retrying (cloudflared retries forever); (b) graceful shutdown closes the H2/QUIC connection right after the unregister RPC instead of waiting out the grace period for in-flight requests (cloudflared waits `gracePeriod` after unregistration on QUIC, `quic_connection.go:91-107`, and waits `activeRequestsWG` on H2, `http2.go:185-190`); (c) `NamedTunnel.endpoint` is deserialized but never consumed for region selection (`tunnel.rs:136-137`; cloudflared resolves `Endpoint` as the region, `cmd/cloudflared/tunnel/configuration.go:197-203`).

## 10. Loopback tests — independence

- `h2_tunnel_end_to_end` (`loopback_test.rs:479-608`): the mock edge is a genuine independent wire client — rustls server + the h2 crate's *client* role driving `h2::client::handshake`, sending a real control-stream request and a real data request, with registration replies replayed as literal capnp-go golden bytes. ## Verdict

Phase B meets the AGENTS.md Phase B goals: shared `Tunnel` abstraction with Serde (`Tunnel`/`QuickTunnel`/`NamedTunnel`, credentials JSON shape byte-compatible with cloudflared), consumer-owned WebSocket and TCP origin handlers with a runtime-agnostic `Duplex`, an HTTP/2 edge connection (server role, SNI `h2.cftunnel.com`, no ALPN — exactly what cloudflared does — with byte-exact classification, header rules, RPC-on-control-stream, and 101→200 remap), and an `EdgeConnector` with discovery, retries, transport selection, EDUPCONN handling, and QUIC→H2 fallback with `run_quick_tunnel` preserved on top. All 47 tests pass, including three genuinely end-to-end loopback tests. The Phase-A review items (features list, originLocalIp, numPreviousAttempts, grace-bounded unregister, CA append semantics, PEM fix) are all addressed and verified against the checkout.

Before Phase C / real-edge validation: (1) decide the backoff/fallback defaults and the discovery-failure retry policy; (2) use `NamedTunnel.endpoint` for region selection; (3) add a read-side cancel for abandoned QUIC request bodies and a drain/RST equivalent for H2 unread bodies (verify h2 crate release-closed-capacity behavior under load); (4) implement graceful-shutdown drain for in-flight requests; (5) tighten the lib.rs runtime-executor doc; (6) consider golden-verifying `send_exception`.
